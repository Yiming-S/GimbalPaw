# OM3 Lab for Apple Silicon

OM3 Lab 是一个原生 macOS 14+ 联调应用，面向 M 系列 Apple Silicon Mac。它使用 CoreBluetooth 控制 DJI Osmo Mobile 3，并使用 AVFoundation 预览直接连接 Mac 的外置 UVC 摄像头。

0.2 版加入基于 Apple Vision 的本机人物跟踪。视频帧不会上传：应用约每 0.15 秒检测一次人物，在画面中标出锁定目标，并通过受限的小角度相对指令让 OM3 自动修正构图。

0.3 版加入 OM3 连接记忆。设备首次通过 FFF0 / FFF4 / FFF5 完整验证后，应用会记住该 Mac 上的 CoreBluetooth UUID；以后启动应用、蓝牙恢复或 OM3 链路意外断开时，都会优先自动连回同一设备。

0.3.1 版将人物跟踪调为快速模式：最大二维修正由 2.0° 提高到 2.5°，动作时长由 0.3 秒缩短到 0.2 秒，命令间隔缩短到 0.35 秒。竖直轴仍限制在最大 2.0°。

0.4 版将跟踪速度改为用户可选的三档：平稳、标准和快速。选择会保存到本机；为避免同一跟踪会话混用不同动作参数，必须先关闭人物跟踪才能切换档位。

0.4.1 版把原“快速”档升级为“极速 +200%”：水平最大修正速率由约 7.1°/s 提高到约 21.4°/s（约为原来的 3 倍）。极速档最高约每 0.08 秒分析一帧，单次合成修正最大 4.5°、Pitch 最大 2.0°、动作 0.1 秒、命令间隔 0.21 秒。新增 0.24 秒初锁时限、0.18 秒反向暂停和累计绝对行程预算，抑制误锁与高速往返。

0.5 版加入出框自动搜索。只有人物从画面水平边缘持续向外移动且方向可信时，云台才会最多惯性补偿 2°；人物持续丢失后，应用会在相对本次跟踪起点的 Yaw ±20° 软件范围内进行慢速左右扫描。发现候选人物时立即 STOP，静止后重新稳定锁定；单轮扫描达到 12 秒、60° 累计行程或两个扫描边界后只暂停运动，人物分析和跟踪开关保持开启，可确认线缆安全后继续扫描。

0.6 版加入多人候选与手动锁定。打开人物跟踪后，预览和控制区会显示本帧可跟踪人物数量，并给每个人分配本次会话内稳定的“人物 N”编号；必须点击其中一个编号后云台才开始跟随。Vision 一旦确认锁定目标漏检，应用会保留未解析锁定并继续执行安全搜索，但不会让旧位置附近的其他人物继承该编号；人物重新出现后需要用户从当前候选中再次点选。

0.7 版把“连续极速”档在 0.6 基础上再提高约 200%：名义远距离水平修正速率由约 21.4°/s 提高到约 65°/s。每个完整控制包交给 CoreBluetooth 后，应用只保留该动作声明的 0.1 秒占用时间，不再增加额外空闲等待；近中心、中距离和远距离分别使用约 1.5°、3.5°、6.5° 的渐进步长，Pitch 仍限制为最大 2.0°。STOP、方向反转、目标丢失和硬安全边界仍会主动打断连续动作。

0.8 版加入“全向安全行程验证”。在 USB 摄像头预览、BLE 和运动安全确认都就绪后，应用按左、右、上、下逐步移动 OM3；Yaw 每步 5°，Pitch 每步 2°，每一步都停下来等待现场人员确认。摄像头会在本机复制 128×72 亮度签名并检查同轴全局画面位移，只把它作为动作响应辅助证据；画面无响应时立即 STOP，且不会继续向外。四个方向返程并由用户逐次确认回正后，应用分别扣除 10° Yaw / 6° Pitch 保护余量，形成非对称菱形跟踪包络。首版最多验证到左右各 100°、上下各 36°，因此最多启用左右各 90°、上下各 30° 的应用安全范围；这是工程上限，不是 OM3 机械限位。

0.8.1 版把首次人物选择改为自动默认：每次打开人物跟踪后，首个非空候选画面会默认锁定候选列表中的第一个人物，即按画面从左到右排序的“人物 1”。仍需通过原有的 3 帧和最短 0.24 秒稳定获取后才驱动云台；用户可随时点击其他人物编号切换。用户主动取消锁定或目标出框后不会再次自动选择，避免旁人接管原目标。

## 连接方式

```text
Mac mini ──BLE 无线──> OM3
Mac mini ──USB 线───> USB 摄像头
OM3      ──USB 线───> 充电器（可选，仅供电）
```

OM3 不通过 USB 接受电脑控制，也不向 Mac 传输摄像头画面。

## 构建

```bash
cd macOS/OM3Lab
./scripts/build-app.sh
```

脚本会先运行协议黄金帧自检，再直接用可用 SDK 构建纯 `arm64` 应用、进行 ad-hoc 签名并输出：

- `outputs/OM3 Lab.app`
- `outputs/OM3-Lab-macOS-arm64.zip`

若本机安装了稳定的 Apple Development 或 Developer ID 证书，可用同一身份签名，以减少重编译后的权限身份变化：

```bash
OM3_SIGN_IDENTITY="Apple Development: Your Name (TEAMID)" ./scripts/build-app.sh
```

默认 ad-hoc 签名适合当前 Mac 上联调，但不等于 Apple 公证。复制到其他 Mac 时，Gatekeeper 可能要求在“隐私与安全性”中手动允许。正式分发需要 Developer ID、Hardened Runtime 和 notarization。

工程同时保留 `Package.swift` 和 XCTest 测试，安装版本匹配的完整 Xcode 后可直接打开或运行 `swift test`。当前打包脚本不依赖 SwiftPM，以避开部分 Command Line Tools 中编译器与默认 SDK 小版本不一致的问题。

## 首次联调

1. 把 USB 摄像头安装到 OM3，先完成机械配平。
2. 摄像头软线接到 Mac mini，并给各转轴留足活动余量。
3. 退出 DJI Mimo，并避免手机先占用 OM3 的蓝牙连接。
4. 打开 OM3 电源，把它放到 Mac mini 附近。
5. 从已打包的 `OM3 Lab.app` 启动；允许蓝牙和摄像头权限。
6. 点击“扫描”，在设备列表中选择 OM3。应用会继续验证 FFF0 / FFF4 / FFF5，直到显示“已就绪”。
7. 确认安全条件后打开“运动安全确认”。先测试单次左/右 5°；空格键或红色按钮发送 STOP。
8. 点击“启用并查找摄像头”，选择外置 UVC 设备并检查预览。
9. 如需扩大默认跟踪范围，把 OM3 人工置中，点击“开始全向验证”，再次确认周围、配平和线缆安全。逐步观察实体和预览；只有实际完成动作且仍有余量时才点击“实体已完成，继续”。每个方向返程后必须确认云台已回到起点。
10. 保持运动安全确认开启，再打开“人物跟踪”。应用会默认选择首个候选“人物 1”；也可点击其他“人物 N”立即切换。目标连续稳定出现 3 帧且满足最短获取时间后，绿色实线框表示已锁定，其他候选使用青色虚线框。

第一次用 0.3 版时需要手动连接成功一次，之后才会自动连接。

## OM3 连接记忆

- 只有完成 FFF0 服务、FFF4 通知、FFF5 无响应写入和 20 字节 ATT 上限验证后，设备 UUID 才会写入本机偏好设置。
- 冷启动后会直接向已记住的 UUID 发起连接；即使 OM3 当时未开机，它稍后开机时 CoreBluetooth 也会继续完成连接。
- 意外掉线使用 macOS 14 的系统自动重连；每次连回后都重新发现和验证 GATT，不复用旧特征对象。
- 应用不会按“OM3”或“DJI”名称自动猜测设备；只会自动连接已验证的 UUID。
- 手动点“断开”或“停止扫描”会取消本次运行的自动连接，但保留记忆；下次启动仍会自动尝试。
- 协议验证失败时会暂停自动重连，避免对不兼容设备循环连接；需要手动重新扫描。
- 自动连接只恢复 BLE 传输。每个新连接会清除旧指令和人物跟踪会话，先发送零速 STOP，并要求用户重新打开“运动安全确认”。

## 人物跟踪行为

- Apple Vision 会输出所有满足置信度和画面面积阈值的可跟踪人物；界面显示本帧候选数量和会话内稳定编号。每次开启跟踪后的首个非空候选画面会自动锁定列表第一项“人物 1”；用户可以点击其他编号切换，或取消锁定后保持等待手动选择。
- 多人编号使用人物框的重叠度和中心距离做一对一跨帧关联。Vision 一旦出现锁定目标漏检，该锁定会变成“未解析”，其他人物不会接管；用户从当前候选重新选择、切换或取消目标时，应用会先撤销旧动作并发送 STOP，再重新稳定获取。
- “人物 N”只是当前摄像头会话内的几何轨迹编号，不是人脸、姓名或生物身份识别。人物交叉、遮挡或出框后，应用无法可靠确认重新出现的候选是否还是原人物，因此不会自动继承旧锁定，需要用户再次点选。
- 人物在右侧时发送正 Yaw；人物在画面上方时发送负 Pitch，与当前实机方向标定一致。
- 中心死区内不动作；死区外根据当前速度档位发送受限的相对修正。
- `平稳`：最大二维修正 1.5°，Pitch 最大 1.0°，动作 0.3 秒，间隔 0.55 秒。
- `标准`：最大二维修正 2.0°，Pitch 最大 1.5°，动作 0.3 秒，间隔 0.45 秒。
- `连续极速 +200%`：近/中/远水平步长约为 1.5° / 3.5° / 6.5°，Pitch 最大 2.0°，每段动作声明 0.1 秒；应用不增加额外空闲等待，名义水平最大修正速率约 65°/s。
- 档位只能在人物跟踪关闭时切换，并会保留为下次启动的默认选择。新安装默认为“连续极速 +200%”；损坏的偏好值回退为“标准”。
- 平稳/标准档的视觉结果最长保留 0.25 秒，连续极速档缩短为 0.10 秒；如果 BLE 堵塞导致修正过时，该指令会被丢弃而不是迟到发送。
- BLE 正在冷却时只保留最新的有效人物修正，并在解锁后重试；新的无人、居中或反向样本会立即取消待发修正。
- 初次锁定必须同时满足连续 3 帧和至少 0.24 秒；检测到运动方向反转后至少暂停 0.18 秒，降低误锁和高速来回摆动。
- 连续两次漏检后，只有最后人物位于水平边缘、最近轨迹持续向外、置信度至少 65%，且与最后实际 Yaw 修正同向时，才会执行最多 2° 的水平惯性补偿；中央遮挡不会盲目续转。
- 人物持续约 0.4 秒未被有效观察时，应用先发送 STOP，再沿离场方向搜索；触及 Yaw ±20° 扫描软边界后停止、稳定并反向扫掠。扫描只使用 `2° / 0.3 秒` 的水平相对动作，间隔 0.45 秒，不做自动 Pitch 搜索。
- 扫描中出现候选人物会立即撤销搜索并发送 STOP。静止 0.3 秒后，候选必须满足至少 5 个稳定帧、持续至少 0.4 秒且置信度至少 65%，才能重新驱动云台；候选消失时恢复扫描。
- 每轮扫描最多运行 12 秒、累计发送 60° 或触及两个软边界。到限后只暂停云台，人物分析和跟踪会话保持开启；确认线缆安全后可点击“继续扫描”。
- 未做全向验证时，单次跟踪使用默认 Yaw 左右各 45°、Pitch 上下各 15° 的基准范围。完成四向验证并确认回正后，下一次跟踪改用实测四方向分别扣除保护余量后的范围，首版应用上限为 Yaw 左右各 90°、Pitch 上下各 30°。由于只验证四个轴向，二维位置使用保守菱形包络，不会同时使用两个轴的完整极限。
- 单次跟踪的绝对累计保险仍保持 Yaw 90°、Pitch 30°，不会因校准范围扩大而提高。硬包络或累计预算触界时只暂停运动但不自动关闭跟踪。
- 校准范围只对紧接着的一次人物跟踪有效，不跨断线或重新启动持久化。范围启用后会锁住手动点动，避免破坏校准原点；STOP、关闭安全确认、BLE 断线、应用进入后台或该次跟踪结束都会使扩展范围失效。人物跟踪结束还会自动关闭运动安全确认，必须人工回正后重新开启；原因是 OM3 没有姿态回传，应用无法在这些事件后证明仍位于校准原点。
- 切换摄像头、停止预览、关闭安全确认、手动 STOP、BLE 断线或应用进入后台，都会关闭跟踪且不会自动恢复。
- 默认按正常横向、非镜像安装的 UVC 摄像头计算方向。若摄像头倒装或其驱动镜像画面，请先关闭人物跟踪并重新校准方向。

## 安全边界

- 运动控制默认锁定，断线或蓝牙关闭会自动复位。
- 当前只开放相对 `±5° / 1.0 秒` 点动，不开放连续速度控制；每次点动还有 1.15 秒软件互锁，避免连续点击累积动作。
- 当前实机方向映射按 `上仰 = Pitch -5°`、`下俯 = Pitch +5°` 显示在联调日志中。
- 任一次手动点动都会使“人物跟踪原点”失效，但仍允许继续做手动联调；开始人物跟踪前必须把云台人工回正，再关闭并重新打开运动安全确认。红色 STOP 会直接关闭运动安全确认，因为中途制动后的实际角度无法从 BLE 得知。
- 全向验证使用独占运动会话：人物跟踪和手动点动会被禁用，红色 STOP 始终可用。每个向外步骤都要等待完整 21 字节包提交、1 秒动作结束、摄像头结论和人工确认，不会预排下一步。
- 全向验证的画面分析只能确认“有/无可验证画面响应”。无响应无法区分机械端点、线缆或障碍物阻塞、BLE 无响应写入未执行、摄像头没有刚性安装以及画面冻结，因此结果明确标记为当前安装条件下的人工安全范围，而不是机械限位。
- Yaw 验证上限 100°、Pitch 验证上限 36° 均低于 OM3 机构的完整标称能力；到达该上限只表示完成本版应用验证，不表示撞到机构端点。应用再扣除 Yaw 10° / Pitch 6° 作为制动、线缆和返程误差余量。
- 人物跟踪同样只使用相对点动，不使用未经实机标定的非零速度模式。
- 连续极速的“无额外等待”是指 0.1 秒相对动作首尾相接，不会并发叠加多条动作。反向、居中、漏检、STOP 和安全预算仍具有更高优先级；OM3 无响应写入没有 ACK，首次使用必须空载验证实际速度和制动距离。
- 自动扫描和跟踪包络的角度来自完整提交相对指令后的积分估计；OM3 没有向应用反馈真实姿态，BLE 无响应写入也没有设备 ACK，因此 ±20° 扫描边界以及默认或校准后的跟踪范围都不是机械限位。首次使用必须空载测试并确认摄像头软线在整个范围内都有余量。
- STOP 使用零速度帧并优先进入发送队列；BLE 的无响应写入没有设备端 ACK，因此它只能作为 best-effort 软件急停。
- 退出或应用转入后台时会尝试发送 STOP，但真正的物理 failsafe 仍是关闭 OM3 电源。
- FFF0 / FFF4 / FFF5 与 DUML 控制帧来自社区逆向研究，不是 DJI 官方桌面控制 API；必须先做空载、低风险验证。

## 排障

- 扫描不到：确认 macOS 已允许 OM3 Lab 使用蓝牙，OM3 已开机，且手机没有连接它。
- 能发现但连接失败：重新启动 OM3，再扫描；不要在 macOS 蓝牙设置中进行传统配对。
- 摄像头列表为空：确认它是 macOS 可识别的 UVC 设备，并检查“系统设置 → 隐私与安全性 → 摄像头”。
- 每次重编后重新询问权限：ad-hoc 签名的代码身份会变化；改用固定 Apple Development 证书、固定 bundle ID 和固定应用路径。
