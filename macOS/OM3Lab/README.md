# OM3 Lab for Apple Silicon

OM3 Lab 是一个原生 macOS 14+ 联调应用，面向 M 系列 Apple Silicon Mac。它使用 CoreBluetooth 控制 DJI Osmo Mobile 3，并使用 AVFoundation 预览用户选择的外置摄像头或 iPhone 连续互通相机。

0.2 版加入基于 Apple Vision 的本机人物跟踪。视频帧不会上传：应用约每 0.15 秒检测一次人物，在画面中标出锁定目标，并通过受限的小角度相对指令让 OM3 自动修正构图。

0.3 版加入 OM3 连接记忆。设备首次通过 FFF0 / FFF4 / FFF5 完整验证后，应用会记住该 Mac 上的 CoreBluetooth UUID；以后启动应用、蓝牙恢复或 OM3 链路意外断开时，都会优先自动连回同一设备。

0.3.1 版将人物跟踪调为快速模式：最大二维修正由 2.0° 提高到 2.5°，动作时长由 0.3 秒缩短到 0.2 秒，命令间隔缩短到 0.35 秒。竖直轴仍限制在最大 2.0°。

0.4 版将跟踪速度改为用户可选的三档：平稳、标准和快速。选择会保存到本机；为避免同一跟踪会话混用不同动作参数，必须先关闭人物跟踪才能切换档位。

0.4.1 版把原“快速”档升级为“极速 +200%”：水平最大修正速率由约 7.1°/s 提高到约 21.4°/s（约为原来的 3 倍）。极速档最高约每 0.08 秒分析一帧，单次合成修正最大 4.5°、Pitch 最大 2.0°、动作 0.1 秒、命令间隔 0.21 秒。新增 0.24 秒初锁时限、0.18 秒反向暂停和累计绝对行程预算，抑制误锁与高速往返。

0.5 版加入出框自动搜索。只有人物从画面水平边缘持续向外移动且方向可信时，云台才会最多惯性补偿 2°；人物持续丢失后，应用会在相对本次跟踪起点的 Yaw ±20° 软件范围内进行慢速左右扫描。发现候选人物时立即 STOP，静止后重新稳定锁定；单轮扫描达到 12 秒、60° 累计行程或两个扫描边界后只暂停运动，人物分析和跟踪开关保持开启，可确认线缆安全后继续扫描。

0.6 版加入多人候选与手动锁定。打开人物跟踪后，预览和控制区会显示本帧可跟踪人物数量，并给每个人分配本次会话内稳定的“人物 N”编号；必须点击其中一个编号后云台才开始跟随。Vision 一旦确认锁定目标漏检，应用会保留未解析锁定并继续执行安全搜索，但不会让旧位置附近的其他人物继承该编号；人物重新出现后需要用户从当前候选中再次点选。

0.7 版把“连续极速”档在 0.6 基础上再提高约 200%：名义远距离水平修正速率由约 21.4°/s 提高到约 65°/s。每个完整控制包交给 CoreBluetooth 后，应用只保留该动作声明的 0.1 秒占用时间，不再增加额外空闲等待；近中心、中距离和远距离分别使用约 1.5°、3.5°、6.5° 的渐进步长，Pitch 仍限制为最大 2.0°。STOP、方向反转、目标丢失和硬安全边界仍会主动打断连续动作。

0.8 版加入“全向安全行程验证”。在所选摄像头预览、BLE 和运动安全确认都就绪后，应用按左、右、上、下逐步移动 OM3；Yaw 每步 5°，Pitch 每步 2°，每一步都停下来等待现场人员确认。摄像头会在本机复制 128×72 亮度签名并检查同轴全局画面位移，只把它作为动作响应辅助证据；画面无响应时立即 STOP，且不会继续向外。四个方向返程并由用户逐次确认回正后，应用分别扣除 10° Yaw / 6° Pitch 保护余量，形成非对称菱形跟踪包络。首版最多验证到左右各 100°、上下各 36°，因此最多启用左右各 90°、上下各 30° 的应用安全范围；这是工程上限，不是 OM3 机械限位。

0.8.1 版把首次人物选择改为自动默认：每次打开人物跟踪后，首个非空候选画面会默认锁定候选列表中的第一个人物，即按画面从左到右排序的“人物 1”。仍需通过原有的 3 帧和最短 0.24 秒稳定获取后才驱动云台；用户可随时点击其他人物编号切换。用户主动取消锁定或目标出框后不会再次自动选择，避免旁人接管原目标。

0.9 版修复人物出框后的找回链路。锁定目标现在可容忍最多 3 帧且不超过 0.35 秒的短暂漏检并原位续锁，检测器单帧闪断不再立即失锁；超过容忍后锁定仍按 0.6 规则退役，旧位置附近的其他人物不会继承该编号。失锁后的自动扫描恢复 0.5 版“发现人物立即 STOP”的行为：画面里只有一个候选时，按 5 帧 / 0.4 秒 / 置信度 65% 稳定确认后自动把锁转移给该候选并恢复跟随；同时出现多个候选时云台保持停止，等待用户点选。人物样本改为主队列直接投递，避免运行循环在事件跟踪期间的延迟把极速档样本拖过新鲜度预算。

0.10 版是一次跨层升级。跟踪能力：检测器关键帧之间加入 Vision 相关跟踪器，锁定目标以全帧率获得位置修正（仅在检测器 0.2 秒内确认过目标时驱动云台，身份、丢失与搜索仍完全由检测器主导）；修正量由三档步进改为经过原标定点的连续比例映射；垂直构图目标上移到画面 42% 高度，为人物保留头部空间。安全修复：运动安全确认以蓝牙控制器为唯一事实源，被拒绝的解锁不再显示为已解锁；STOP 按钮与空格键在任何连接状态都可用；应用退出时补发 best-effort STOP。全向验证：新增步前静止检查、位移方向一致性与正交轴位移检查；实测位移明显小于此前步幅时按疑似端点处理且不计入行程；操作员在“已移动”一步选择停止时，该步不计入包络但返程仍会返还其行程；单方向行程不足只重试该方向，不再作废整场；返程按最多 3 步合并为大步相对移动（角速度与探测一致）；回正复核强制使用返程稳定后的新帧；标定期间锁定摄像头曝光与白平衡；新增“重试本步”；基线与返程中的采样超时不再卡死界面；完成时先校验包络再拆除会话，失败路径保证发出 STOP。性能：视觉样本改为主线程直达回调，不再触发全界面每帧重建；跟踪状态仅在值变化时通知界面；TX/RX 逐包日志默认关闭（日志区可开启）；预览覆盖层做差量更新。交互：点击预览中的人物框可直接选择或切换目标；扫描暂停与运动暂停以预览横幅显示完整原因和“继续扫描”/“结束本次跟踪”操作；跟踪或验证运行时锁定摄像头切换；应用失焦自动停止后显示提示横幅。

0.11 版专注跟踪平顺性，共六项：修正改为预测瞄准——用 One Euro 滤波的速度估计把目标点前移约 0.18 秒（前移量上限 12% 画幅），显著减小匀速行走时的稳态滞后；死区加入迟滞（水平 0.12 出 / 0.07 回，垂直 0.15 出 / 0.09 回），并把比例曲线的最小步幅从 1.5° 降到 0.5°（平稳/标准档 0.3°），消除死区边界的往复抖动和起步踢；方向反转改为按轴处理——小于 1° 的反转只把该轴静置一拍、另一轴继续，只有大幅反转才走 STOP + 0.18 秒暂停；锁定目标的控制锚点用 One Euro 滤波（速度自适应：静止重滤波、快动轻滤波）替代固定 EMA（显示框仍用原平滑）；垂直控制锚点从人物框中心改为头部位置（框上沿向下 1/4 框高，目标 32% 画幅高度），抬手、转身引起的框高变化不再造成俯仰点头；相邻指令间修正幅度增长限制在每拍 2°（衰减不限制），加速度曲线被磨平。One Euro 的速度导数按原始信号差分计算（非经典的滤波值差分），避免前馈系统性超前。同时把视觉管线的“有回调”与“有可安全驱动运动的新鲜样本”分开记录：过时样本不能维持自动扫描，新鲜样本超时会立即 STOP 并暂停扫描。

0.11.2 版降低全向验证的人工作量。运动安全与开始确认完成后，可信的同轴步进会自动进入下一步；返程画面连续两次匹配本方向起点时自动切换到下一方向。命令发送前的互锁、帧、静止度或分析瞬态问题会自动退避并重新取新基线；命令已经入队后只允许 STOP 并重新取样，绝不会自动重复发送该步。通常只需在四个方向出现“完全无位移”时分别确认一次；正交、反向、部分位移、返程不一致、会话失效或 STOP 失败仍保持人工恢复或 fail-closed。

0.11.3 版进一步减少现场干预：App 因切换窗口或系统弹窗暂时失去焦点时会立即 STOP，但不再退出或清空整次验证；已完成方向保留，只需回到 App、重新打开运动安全确认并人工回正，即可重试当前方向。无人值守位移必须通过正反双向画面配准，中心遮挡或数字裁切不能被记成云台移动；校准期间禁用的 Center Stage 也会在恢复完成后才释放跟踪互锁。摄像头列表保留全部候选；用户最后一次明确选择并成功运行的设备会被记住，冷启动只自动恢复这台设备，暂时缺失时不会擅自改用 Anker 或其他候选。

0.12 版新增“追踪 50×”速度档并把现有安装一次性迁移到该档。这里的 50× 按原“平稳”档在相同比例曲线节点的名义角速度计算：最小、居中和最大修正约为 50 倍，Yaw 最高约 13.7°/0.1 秒，Pitch 最高约 9.1°/0.1 秒，动作之间没有应用层空闲间隔。该档同时放开旧加速度瓶颈，并按 50 倍扩展累计行程预算，使满速运行到预算暂停的时间与原平稳档接近；净位姿仍被同一个 ±45°/±15° 默认菱形或实测标定包络硬限制。OM3 的实际机械速度可能低于名义请求；摄像头帧新鲜度、反向 STOP 和丢帧保护继续生效。速度仍可在关闭人物跟踪后手动切回平稳、标准或连续极速。

0.13 版以 DJI 官方规格重新定义运动边界，并覆盖 0.12 版的当前行为。DJI 公布的 OM3 结构活动范围为 Pan `-162.5° .. 170.3°`、Tilt `-104.5° .. 235.7°`，最大控制速度为 `120°/s`；这些角度基于 DJI 的结构参考，不是从 App 当前回中点起的对称可控边界，且 DJI 对 OM3 的 Tilt“可控转动范围”标记为 N/A，因此 App 只把它们当作绝对合理性上限。四方向安装态标定的向外探测上限改为左 150°、右 160°、上 98°、下 228°；扣除端点余量后，跟踪最大包络分别为左 140°、右 150°、上 92°、下 222°。未标定时使用回中点起左右各 120°、上下各 60° 的保守包络。人物跟踪现在同时驱动 Pan 与 Tilt，垂直死区缩小为外 8% / 内 4%；目标出框时可按最后可信的左、右、上或下方向惯性寻找，并在当前安全包络内执行 5° / 0.1 秒、无额外应用等待的二维扫描，不再使用固定 Yaw ±20° 搜索范围。单轮自主搜索上限扩展到 180 秒 / 3000° 累计指令行程，且仍受更严格的分轴累计保险、画面新鲜度和净位姿包络约束。“追踪 50×”仍保持无额外应用层等待，但所有二维运动指令受官方 `120°/s` 硬封顶。

0.14 版将跟踪速度简化为平稳、标准、连续极速三档并移除“追踪 50×”。三档现在共用连续极速已经验证的 0.1 秒控制节拍：每个动作声明 0.1 秒，传输互锁也恰好保持 0.1 秒，因此动作首尾衔接且没有应用层空闲间隔；平稳和标准只用更小的 Yaw/Pitch 修正降速。旧版保存的第四档会在启动时自动迁移到连续极速，原本明确选择的平稳、标准或连续极速继续保留。

0.15 版重新整理 macOS 界面层级。一级控制栏只保留 OM3 连接、运动安全确认、硬边界摘要、人物选择和三档跟踪；固定点动、全向安全验证、精确四向角度、人物误差遥测及 BLE 日志统一移入“高级与帮助”二级页面。二级页面只替换右侧控制栏，不遮挡摄像头预览。验证运行时，一级仍显示当前方向和进度；红色云台 STOP 在一级和二级页面底部都固定可见，空格键随时可以触发。摄像头的普通停止按钮改名为“停止预览”，避免与云台急停混淆。

0.15.1 版加入 GimbalPaw 专属 macOS 图标：以镜头化爪印作为主体，用青色取景框和双轴运动轨迹表达人物识别与云台追踪。1024 px 透明主稿和完整 `.icns` 均保存在 `Resources/`，打包脚本会验证并复制图标到 App bundle。

## 连接方式

```text
Mac mini ──BLE 无线──> OM3
Mac mini ──Continuity Camera / USB───> 所选摄像头
OM3      ──USB 线───> 充电器（可选，仅供电）
```

OM3 不通过 USB 接受电脑控制，也不向 Mac 传输摄像头画面。

## 构建

```bash
cd macOS/OM3Lab
./scripts/build-app.sh
```

脚本会先运行协议黄金帧自检，再直接用可用 SDK 构建纯 `arm64` 应用、进行 ad-hoc 签名并输出：

- `outputs/OM3 Lab.app`
- `outputs/OM3-Lab-macOS-arm64.zip`

若本机安装了稳定的 Apple Development 或 Developer ID 证书，可用同一身份签名，以减少重编译后的权限身份变化：

```bash
OM3_SIGN_IDENTITY="Apple Development: Your Name (TEAMID)" ./scripts/build-app.sh
```

默认 ad-hoc 签名适合当前 Mac 上联调，但不等于 Apple 公证。复制到其他 Mac 时，Gatekeeper 可能要求在“隐私与安全性”中手动允许。正式分发需要 Developer ID、Hardened Runtime 和 notarization。

工程同时保留 `Package.swift` 和 XCTest 测试，安装版本匹配的完整 Xcode 后可直接打开或运行 `swift test`。当前打包脚本不依赖 SwiftPM，以避开部分 Command Line Tools 中编译器与默认 SDK 小版本不一致的问题。

## 首次联调

1. 把作为取景设备的 iPhone 或外置摄像头安装到 OM3，在水平、周围净空的稳定表面上完成机械调平和载荷配平。
2. 使用足够柔软的摄像头线、充电线或其他连接线，并给每个转轴在完整计划行程内留足活动余量。
3. 退出 DJI Mimo，并避免手机先占用 OM3 的蓝牙连接。
4. 打开 OM3 电源，把它放到 Mac mini 附近。
5. 从已打包的 `OM3 Lab.app` 启动；允许蓝牙和摄像头权限。
6. 点击“扫描”，在设备列表中选择 OM3。应用会继续验证 FFF0 / FFF4 / FFF5，直到显示“已就绪”。
7. 确认安全条件后打开“运动安全确认”。如需先做单次左/右 5° 调试，从“高级与帮助 → 手动控制”进入；空格键或主界面底部红色按钮发送 STOP。
8. 点击“启用并查找摄像头”，从完整候选列表中选择 `Yiming的iPhone Camera` 或需要的其他设备。成功预览后应用会记住该选择；以后只自动恢复这台设备，不会在它缺失时自行回退。
9. 如需按当前安装确认完整跟踪范围，把 OM3 人工置中，从“高级与帮助 → 全向安全”点击“开始全向验证”，再次确认周围净空、机身调平、载荷配平和柔软线缆余量。标定会分别探测左、右、上、下，探测上限为 150° / 160° / 98° / 228°；可信步进和画面确认回正会自动继续，每个方向到达实体无响应边界时仍需现场确认。失焦只暂停并保留已完成方向，不再退出整次验证。
10. 保持运动安全确认开启，再打开“人物跟踪”。应用会默认选择首个候选“人物 1”；也可点击其他“人物 N”立即切换。目标连续稳定出现 3 帧且满足最短获取时间后，绿色实线框表示已锁定，其他候选使用青色虚线框。

更换手机、保护壳或摄像头等载荷，改变横屏/竖屏安装，重新折叠展开云台，或改变底座姿态后，都要重新调平、人工回中并执行一次新的四方向标定；旧结果不能证明新安装仍安全。

第一次用 0.3 版时需要手动连接成功一次，之后才会自动连接。

## OM3 连接记忆

- 只有完成 FFF0 服务、FFF4 通知、FFF5 无响应写入和 20 字节 ATT 上限验证后，设备 UUID 才会写入本机偏好设置。
- 冷启动后会直接向已记住的 UUID 发起连接；即使 OM3 当时未开机，它稍后开机时 CoreBluetooth 也会继续完成连接。
- 意外掉线使用 macOS 14 的系统自动重连；每次连回后都重新发现和验证 GATT，不复用旧特征对象。
- 应用不会按“OM3”或“DJI”名称自动猜测设备；只会自动连接已验证的 UUID。
- 手动点“断开”或“停止扫描”会取消本次运行的自动连接，但保留记忆；下次启动仍会自动尝试。
- 协议验证失败时会暂停自动重连，避免对不兼容设备循环连接；需要手动重新扫描。
- 自动连接只恢复 BLE 传输。每个新连接会清除旧指令和人物跟踪会话，先发送零速 STOP，并要求用户重新打开“运动安全确认”。

## 人物跟踪行为

- Apple Vision 会输出所有满足置信度和画面面积阈值的可跟踪人物；界面显示本帧候选数量和会话内稳定编号。每次开启跟踪后的首个非空候选画面会自动锁定列表第一项“人物 1”；用户可以点击其他编号切换，或取消锁定后保持等待手动选择。
- 多人编号使用人物框的重叠度和中心距离做一对一跨帧关联。锁定目标可容忍最多 3 帧且不超过 0.35 秒的短暂漏检并原位续锁；超过容忍后锁定变成“未解析”，其他人物不会直接接管该编号。用户从当前候选重新选择、切换或取消目标时，应用会先撤销旧动作并发送 STOP，再重新稳定获取。
- “人物 N”只是当前摄像头会话内的几何轨迹编号，不是人脸、姓名或生物身份识别。人物交叉、遮挡或出框超过漏检容忍后，应用无法从几何轨迹确认重新出现的候选是否还是原人物：画面里只有一个候选时会按稳定条件自动转移锁定并恢复跟随，同时出现多个候选时保持停止并等待用户点选。
- 人物在右侧时发送正 Yaw，人物在画面上方时发送负 Pitch；跟踪修正会同时保留 Pan 与 Tilt 分量，不再只做水平跟随。
- 中心死区带迟滞：误差超过外死区（水平 12% / 垂直 8%）才开始修正，回到内死区（水平 7% / 垂直 4%）才停止。修正量按预测误差连续比例给出（经过原有标定点的分段线性，最小步幅约 0.5°），并用滤波速度把目标点前移约 0.18 秒；相邻指令间幅度增长受限。小于 1° 的方向反转只静置该轴一拍，大幅反转仍走 STOP 加 0.18 秒暂停。
- 垂直控制锚点是人物头部（框上沿向下 1/4 框高），目标位于画面 32% 高度，为人物保留头部空间；框高变化（抬手、转身）不会引起俯仰点头。
- 检测器每约 0.08 秒输出一次完整候选；其间的相机帧由 Vision 相关跟踪器以全帧率跟随锁定目标。跟踪器只提供位置修正，不参与身份、丢失或搜索判定；检测器超过 0.2 秒未确认目标时，跟踪器输出立即失效。
- `平稳`：最大二维修正 1.5°，Pitch 最大 1.0°，动作 0.1 秒，首尾连续，无额外等待。
- `标准`：最大二维修正 2.0°，Pitch 最大 1.5°，动作 0.1 秒，首尾连续，无额外等待。
- `连续极速`：水平修正在约 1.5°–6.5° 间随误差连续缩放，Pitch 最大 2.0°，动作 0.1 秒，首尾连续，无额外等待；名义水平最大修正速率约 65°/s。
- 档位只能在人物跟踪关闭时切换，并会保留为下次启动的默认选择。旧版保存的第四档或损坏的偏好值会迁移到“连续极速”；已经选择的平稳、标准或连续极速不会被覆盖。
- 三档视觉结果都只保留 0.10 秒；如果 BLE 堵塞导致修正过时，该指令会被丢弃而不是迟到发送。
- 视觉管线到达活性只用于诊断；自动扫描必须持续收到满足新鲜度预算的样本。过时样本既不驱动云台，也不能维持扫描；新鲜样本超时会立即 STOP 并暂停扫描，等待用户确认后再继续。
- BLE 正在冷却时只保留最新的有效人物修正，并在解锁后重试；新的无人、居中或反向样本会立即取消待发修正。
- 初次锁定必须同时满足连续 3 帧和至少 0.24 秒；检测到运动方向反转后至少暂停 0.18 秒，降低误锁和高速来回摆动。
- 连续两次漏检后，只有最后人物位于画面左、右、上、下边缘之一，最近轨迹持续向外、置信度至少 65%，且与最后实际 Pan 或 Tilt 修正同向时，才会沿最可信离场方向执行最多 6° 的惯性补偿；中央遮挡不会盲目续转。
- 人物持续约 0.4 秒未被有效观察时，应用先发送 STOP，再沿最后可信的左、右、上或下方向寻找；随后在当前跟踪安全包络内以 5° / 0.1 秒的步幅执行覆盖 Pan 与 Tilt 的二维扫描。搜索不再使用固定 Yaw ±20° 软边界，任一方向触及自己的包络边界时会转向其余可用方向。
- 扫描中出现候选人物会立即撤销搜索并发送 STOP。静止 0.3 秒后，候选必须满足至少 5 个稳定帧、持续至少 0.4 秒且置信度至少 65%，才能把锁定转移给它并重新驱动云台；候选消失时恢复扫描。同时出现多个候选时不做自动选择，云台保持停止并提示点选目标。
- 扫描持续受画面新鲜度、净位姿包络、累计运动预算、反向 STOP 和 BLE 状态保护；任一安全条件触发时只暂停云台，人物分析和跟踪开关不会自动关闭。条件恢复并确认安装安全后可以继续寻找。
- 未做全向验证时，单次跟踪使用回中点起左 120°、右 120°、上 60°、下 60° 的保守范围。四方向验证的向外探测上限分别为左 150°、右 160°、上 98°、下 228°；确认回正并扣除 Yaw 10° / Pitch 6° 端点余量后，标定跟踪包络的最大值分别为左 140°、右 150°、上 92°、下 222°。由于只验证四个轴向，二维位置继续使用保守菱形包络，不会同时使用两个轴的完整极限。
- 累计运动预算是独立于净位姿包络的保险，扩大的标定范围不会绕过它。硬包络或累计预算触界时只暂停运动，不自动关闭人物分析或跟踪开关。
- 校准范围只对紧接着的一次人物跟踪有效，不跨断线或重新启动持久化。范围启用后会锁住手动点动，避免破坏校准原点；STOP、关闭安全确认、BLE 断线、应用进入后台或该次跟踪结束都会使扩展范围失效。人物跟踪结束还会自动关闭运动安全确认，必须人工回正后重新开启；原因是 OM3 没有姿态回传，应用无法在这些事件后证明仍位于校准原点。
- 切换摄像头、停止预览、关闭安全确认、手动 STOP、BLE 断线或应用进入后台，都会关闭跟踪且不会自动恢复。
- 默认按正常横向、非镜像安装的摄像头计算方向。若摄像头倒装或输出镜像画面，请先关闭人物跟踪并重新校准方向。

## 安全边界

- 运动控制默认锁定，断线或蓝牙关闭会自动复位。
- 任何自动运动前都要确保 OM3 周围完整行程净空、底座稳定且调平、载荷机械配平，并只使用有充分活动余量的柔软线缆。更换载荷、横屏/竖屏方向或底座姿态后必须重新调平、人工回中和四方向标定。
- 当前只开放相对 `±5° / 1.0 秒` 点动，不开放连续速度控制；每次点动还有 1.15 秒软件互锁，避免连续点击累积动作。
- 当前实机方向映射按 `上仰 = Pitch -5°`、`下俯 = Pitch +5°` 显示在联调日志中。
- 任一次手动点动都会使“人物跟踪原点”失效，但仍允许继续做手动联调；开始人物跟踪前必须把云台人工回正，再关闭并重新打开运动安全确认。红色 STOP 会直接关闭运动安全确认，因为中途制动后的实际角度无法从 BLE 得知。
- 全向验证使用独占运动会话：人物跟踪和手动点动会被禁用，红色 STOP 始终可用。每个向外步骤都要等待完整 21 字节包提交、动作互锁结束和摄像头结论；可信同轴位移自动继续，但不会预排动作。无位移边界、几何冲突或返程不一致仍等待现场确认。
- 全向验证的画面分析只能确认“有/无可验证画面响应”。无响应无法区分机械端点、线缆或障碍物阻塞、BLE 无响应写入未执行、摄像头没有刚性安装以及画面冻结，因此结果明确标记为当前安装条件下的人工安全范围，而不是机械限位。
- DJI 公布的结构活动范围是 Pan `-162.5° .. 170.3°`、Tilt `-104.5° .. 235.7°`，最大控制速度是 `120°/s`。这些角度不是从 App 当前回中点起的对称边界，且 DJI 将 OM3 的 Tilt 可控转动范围标为 N/A；App 只把结构数值用于绝对合理性检查，不能据此假定某次安装一定可达。
- 四方向验证从确认的安装态回中点分别探测，硬探测上限为左 150°、右 160°、上 98°、下 228°；到达探测上限只表示完成 App 验证，不表示撞到结构端点。应用再扣除 Yaw 10° / Pitch 6° 作为制动、线缆和返程误差余量，因此可交给跟踪的最大标定包络为左 140°、右 150°、上 92°、下 222°。
- 人物跟踪同样只使用相对点动，不使用未经实机标定的非零速度模式。
- 高速档的“无额外等待”是指相对动作首尾相接，不会并发叠加多条动作；Pan/Pitch 合成请求仍受 `120°/s` 硬封顶。反向、居中、漏检、STOP 和安全预算具有更高优先级；OM3 无响应写入没有 ACK，首次使用必须低风险验证实际速度和制动距离。
- 自动扫描和跟踪包络的角度来自完整提交相对指令后的积分估计；OM3 没有向应用反馈真实姿态，BLE 无响应写入也没有设备 ACK，因此未标定的左/右 120°、上/下 60° 包络以及标定后的非对称包络都不是机械限位。首次使用必须低风险测试并确认摄像头软线在整个范围内都有余量。
- STOP 使用零速度帧并优先进入发送队列；BLE 的无响应写入没有设备端 ACK，因此它只能作为 best-effort 软件急停。
- 退出或应用转入后台时会尝试发送 STOP，但真正的物理 failsafe 仍是关闭 OM3 电源。
- FFF0 / FFF4 / FFF5 与 DUML 控制帧来自社区逆向研究，不是 DJI 官方桌面控制 API；必须先做空载、低风险验证。

## 排障

- 扫描不到：确认 macOS 已允许 OM3 Lab 使用蓝牙，OM3 已开机，且手机没有连接它。
- 能发现但连接失败：重新启动 OM3，再扫描；不要在 macOS 蓝牙设置中进行传统配对。
- 摄像头列表为空：确认 iPhone 连续互通相机已可用，或设备是 macOS 可识别的 UVC 摄像头，并检查“系统设置 → 隐私与安全性 → 摄像头”。
- 每次重编后重新询问权限：ad-hoc 签名的代码身份会变化；改用固定 Apple Development 证书、固定 bundle ID 和固定应用路径。
